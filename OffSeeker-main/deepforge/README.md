# DeepForge

DeepForge is a framework for generating high-quality, challenging web search QA datasets. The framework constructs entity-centric knowledge graphs and generates complex questions that require deep web search and multi-hop reasoning.

## 📖 Project Overview

### Purpose

DeepForge aims to generate QA datasets that test models' deep web search capabilities. Unlike traditional QA datasets, the questions generated by this project have the following characteristics:

- **Long-tail Entity Focus**: Based on low-frequency, obscure entities rather than well-known entities
- **Multi-hop Reasoning**: Questions require reasoning through relationships between multiple entities
- **Ambiguity Design**: Uses ranges, relative terms, and avoids exact numbers and dates
- **Search Necessity**: Generated questions cannot be answered through internal knowledge or guessing alone

### Implementation

The project implements a complete 6-step data generation pipeline:

```
1. URL Generation       → Generate random nouns, search for URLs
2. Entity Extraction    → Crawl URL content, extract long-tail entities
3. Entity Graph Build   → Multi-hop exploration to build entity knowledge graphs
4. QA Generation        → Generate complex QA pairs based on entity graphs
5. Difficulty Enhance   → Enhance question difficulty (remove specific clues)
6. Quality Filter       → Filter out questions that are too easy
```

Core features:

- ✅ **Modular Architecture**: Clean code organization, easy to maintain and extend
- ✅ **Centralized Configuration**: All configs in `config/` directory
- ✅ **Multi-LLM Support**: Supports Gemini, OpenAI, DeepSeek, vLLM
- ✅ **Concurrent Processing**: Supports large-scale parallel generation
- ✅ **Complete Pipeline Demo**: Provides single-step demo scripts

## Quick Start

### 1. Configure API Keys

Copy the environment variable template and fill in your API keys:

```bash
cp .env.example .env
```

Edit `.env` file and add required configurations:

```bash
# Serper API (Google Search) - Required
SERPER_API_KEY="your_serper_api_key"

# OpenAI-Compatible API (Gemini) - Required
OPENAI_API_KEY="your_openai_api_key"
OPENAI_BASE_URL="your_base_url"

# Jina API (Content Extraction) - Required
JINA_API_KEY="your_jina_api_key"

# DeepSeek API (Optional)
DEEPSEEK_API_KEY="your_deepseek_api_key"
DEEPSEEK_BASE_URL="https://api.deepseek.com"
```

### 2. Run Pipeline Demo

View the complete pipeline:

```bash
python scripts/demo.py
```

This script will:
1. Generate 5 random nouns and search for URLs
2. Process 3 URLs and extract long-tail entities
3. Process 2 entities, build entity graphs and generate QA pairs
4. Enhance QA difficulty

All intermediate results are saved in `data/show_case/` directory.

### 3. Complete Pipeline Run

#### Way 1: Demo Workflow (Recommended for Beginners)

Run the complete demo (includes first 4 steps, automatically saves all intermediate results):

```bash
python scripts/demo.py
```

Output files (saved in `data/show_case/`):
- `step1_urls.jsonl` - URLs generated in Step 1
- `step2_seed_entities.jsonl` - Seed entities extracted in Step 2
- `step3_entity_graphs.jsonl` - Entity graphs built in Step 3
- `step3_qa_pairs.jsonl` - QA pairs generated in Step 3
- `step4_qa_enhanced.jsonl` - QA pairs with enhanced difficulty from Step 4

#### Way 2: Production Workflow

Use standalone scripts for large-scale production:

```bash
# Step 1: Generate URLs
python scripts/generate_urls.py \
    --num-nouns 100 \
    --urls-per-noun 10 \
    --output data/urls.jsonl

# Step 2: Extract seed entities
python scripts/generate_seed_entities.py \
    --input data/urls.jsonl \
    --output data/seed_entities.jsonl \
    --num-urls 50

# Step 3 & 4: Generate entity graphs and QA pairs (main step)
python scripts/generate_qa.py \
    --seed-entities tmp/seed_entities.json \
    --output data/qa_pairs_all.jsonl \
    --graphs tmp/seed_entities_graph.jsonl

# Step 5: Difficulty enhancement (optional)
python scripts/enhance_difficulty.py \
    --input data/qa_pairs_all.jsonl \
    --output data/qa_pairs_enhanced.jsonl

# Step 6: Quality filtering (optional)
python scripts/filter_quality.py \
    --input data/qa_pairs_enhanced.jsonl \
    --output data/qa_pairs_hard.jsonl
```

Output file descriptions:
- `data/urls.jsonl` - URLs generated in Step 1
- `data/seed_entities.jsonl` - Seed entities extracted in Step 2
- `tmp/seed_entities.json` - Seed entities in JSON format (for Step 3 use)
- `data/qa_pairs_all.jsonl` - Initially generated QA pairs
- `data/qa_pairs_enhanced.jsonl` - QA pairs after difficulty enhancement
- `data/qa_pairs_hard.jsonl` - Final QA pairs after quality filtering
- `tmp/seed_entities_graph.jsonl` - Entity graph intermediate results



## 💡 Usage Examples

### Generate a Single QA

```python
from src.entities.explorers import gather_information
from src.qa_generation.generators import generate_qa_pair

# Explore entity (multi-hop web search)
graph = gather_information("capybara", depth=2)

# Generate QA pair
question, answer = generate_qa_pair(graph)

print(f"Question: {question}")
print(f"Answer: {answer}")
```

### Use Custom API

```python
from api.caller import APICaller

# Use different model
caller = APICaller(
    api_type="",
    model_name="",
    api_key="your_key",
    base_url="https://your-endpoint.com/v1"
)

response = caller.call_api([{"role": "user", "content": "Hello"}])
```

## 📊 Output Format

Generated QA pairs are in JSONL format:

```json
{
  "entity": "entity_name",
  "question": "question",
  "answer": "answer",
  "depth": 2,
  "extra_info": {
    "entity_dict": {...},
    "transition_path": [...]
  }
}
```
